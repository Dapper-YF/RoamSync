# RoamSync 60–90 秒真实录屏脚本

当前没有录制 MP4 或 GIF。本脚本供后续在隔离环境真实操作后执行；不允许预先拼好候选卡片或叠加伪造的成功状态。

## 开始前

1. 仅在新建的本地演示环境中运行，使用空白数据库或 Compose 测试配置的临时数据库。不要连接当前 `roamsync` 项目、不要使用其 `roamsync_postgres_data` 数据卷，也不要在当前服务上执行 `app.seed_demo --reset`。
2. 如需真实模型候选，配置自己的 `PLANNER_API_KEY`；地点和路线需要可用的 `AMAP_REST_KEY`。只有真实 Provider 返回、Validator 显示通过并出现待确认 Revision，才继续录制成功路径。任何失败照实展示或停止，不可切换到静态/模拟接口。
3. 用程序自带的合成演示种子（仅在隔离库）建立两日旅行；录制前确认展示标题、地点、日期和金额都是可公开的合成数据。不得展示账号、地址、真实行程、密钥、浏览器个人资料或原始轨迹。
4. OBS 或其他录屏设置：16:9、1600×900 或 1920×1080、30 fps；隐藏浏览器书签栏、个人资料图标和开发者工具。录制整段操作，不剪接成功状态。

## 60–90 秒镜头顺序

| 时间 | 操作与讲解 |
| --- | --- |
| 0–8 秒 | 显示隔离演示旅行主页。讲：“这是两日合成旅行；这里是正式日程，Agent 还没有修改它。” |
| 8–20 秒 | 打开旅程总管，输入“请帮我调整一下行程”。如果系统追问目标日期/调整内容，停留在真实澄清消息上，讲“请求缺少范围时先问清楚”。 |
| 20–32 秒 | 回复：“调整第一天：节奏轻松些，减少连续步行，保留已有地点，预算不要增加。”若系统提出更多必要问题，按真实问题回答；不要用脚本提前预填 UI。 |
| 32–55 秒 | 等待真实 PlanningRun。展示正在发生的阶段和候选约束检查；如最后出现有效 Revision，展示日期/活动/路线/预算差异，并指出状态是待确认。此时切到行程列表证明正式版尚未变化。 |
| 55–68 秒 | 口播“候选有效也不会直接写进正式行程”。点击真实“确认并应用”按钮。展示接受结果及 Trip/Revision 状态。 |
| 68–82 秒 | 刷新页面或重新进入旅行，等待后端重新读取。展示接受后的活动仍存在；仅在画面真实返回后说“刷新后仍存在”。 |
| 82–90 秒 | 收束：“路由和约束由后端控制；模型只给候选；正式写入经过用户确认。” |

### 合成需求文本

首条输入（故意未给调整范围，以产生必要澄清）：

> 请帮我调整一下行程。

澄清后的回答：

> 调整第一天：节奏轻松些，减少连续步行，保留已有地点，预算不要增加。先给候选，等我确认。

按界面真实问题补齐信息。当前实现与 Provider 可能要求不同输入；不要为了赶时间伪造“澄清”环节。如果没出现澄清，停下检查实际状态并如实说明。

## 失败停止条件

- 模型/地图服务不可用、规划任务超时、候选非法或 Validator 拒绝：保留真实失败状态。不可制作“确认成功”画面。
- 点击确认后出现 409/422 或刷新后候选消失：保留错误并停止成功叙事。
- 如果没有拿到真实的接受后刷新状态，则完整 MP4 标注未完成，不补录假刷新镜头。
- 延误影响/局部调整属于可选第二段；仅在隔离行程里走实际延误事实与 Recovery 候选流程后录制。导航模拟不得说成真实 GPS 或实际交通延误。

## 从真实 MP4 导出 12 秒 GIF

在完整 MP4 已检查通过后，按实际时间码替换 `-ss` 起点。下面的命令只从真实 MP4 截取，不生成新 UI 状态；尺寸/帧率可继续降低到 8 MB 以内：

```powershell
ffmpeg -ss 00:00:55 -t 12 -i RoamSync-demo.mp4 -vf "fps=12,scale=960:-1:flags=lanczos,split[s0][s1];[s0]palettegen=max_colors=128[p];[s1][p]paletteuse=dither=bayer" -loop 0 RoamSync-demo.gif
```

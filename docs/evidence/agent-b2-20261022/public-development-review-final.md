Each row has a strict, task-specific basically-usable yes/no decision. A yes requires the current request's material intent and conditions to survive, tools to respect the request, facts to stay within the available evidence, a useful answer/action boundary, and appropriate write authority. A failed material dimension makes the turn no; an exception-free response alone cannot pass. Initial condition intake and broad condition recall must retain explicit companion information. A later narrow query about date/budget/walking can pass when those requested fields are correct, while an unrelated companion defect remains disclosed.

Dimension order in the table is **I / T / V / F / U / W**: intent; tool selection/execution; valid conditions and memory; fact assurance; usefulness; write authorization. `✓` means sufficient for that turn, `✗` a material failure, and `—` no substantive fact claim to assess. Tool `✓` includes correctly doing no external read when none is needed. Write `✓` means the captured boundary is appropriate; it does not prove a later adopt/modify/reload chain.

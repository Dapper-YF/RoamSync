# Android 原生产品重构：本轮实际交付

正式产品基准已于2026-10-18统一至 E:/Study/RoamSync 的3000，新版Web已部署。
Android随后基于该代码/契约重做；正式目录现拥有新版Android源码，独立构建成功。
本轮不是Android全量验收完成声明。

## 真正退出用户路径的旧界面

- 旧MobileApp入口函数已删除；TourismApp只调用FormalJourneyNative。
- 旧TripsHome、TripDetail模块标签、手动创建正式旅行、活动直改弹窗、独立预算与技术执行面板均从该组件删除。
- 旅程改为正在筹划/即将出发/正在旅行/历史旅行，默认筹划，主入口为筹划新旅行。
- 正式旅行单页依次组织有效要求、当前/下一站、影响及Recovery差异、正式日程、准备信息和明确调整。
- 单一全局AI会话保留地点/草稿/正式旅行上下文；地点详情的往返使用明确页面返回上下文。
- 探索首次为空，不预设杭州/西湖，不自动要求Trip、定位或调用搜索；城市选择改为底部弹层，主搜索更紧凑。

保留ViewModel/API/执行、版本与确认规则。未为Android复制Planner或正式业务规则。页面属于原生Compose；地图仍复用原有地图适配，不是整站WebView。

## 验证范围

- 正式目录Android构建及测试：49 tests，0 failures；debug与androidTest APK生成成功。
- 真机只安装`com.roamsync.app.v2preview`，API18004隔离服务、专用真实地点测试旅行。原正式手机应用未覆盖或清数据。
- 探索：真实成都地点搜索→详情/审核照片→收藏→地图→设起点→另一真实地点→步行路线→情境AI真实回答→返回详情与搜索，搜索内容保留。
- 规划：恢复专用草稿→修改要求→探索往返未保存内容保留→核对保存→日期和完整预览→明确创建并采用→新版正式日程。
- 执行：手动到达/开始→延长60分钟→服务端不可行检测→真实模型Recovery→核对前后差异→明确采用→完成首站→到达并开始下一站→切后台并正常返回，当前活动保留。首次后台恢复测试受OEM阻止自动启动影响而失败，修正测试启动方式后重新完整通过；失败不能被当作通过记录。
- 前台定位重试实际取得约30米精度的系统network位置，时间与来源可见；权限为用户此前亲自授予，测试没有ADB授权/注入坐标。当前位置到下一站的Provider路线失败，与定位成功分别显示。先前定位尝试未取得合格结果，不能隐去该失败。
- 确认安全：未知结果保存原run/choice，查询前禁重复POST；普通与Recovery共用恢复逻辑。单元验证失响应/离线阻止二次POST，ViewModel重建后读取原终态。不是完整手机进程死亡测试。

证据：`docs/evidence/android-unified-20261018/`。各run.json记录实际APK哈希；早期探索与最终源码/正式目录构建APK不同，分别保留，不混称同一APK。正式源码与交付APK对应信息见android-source-binding.json。

## 未完成与体验差距

- 当前位置→下一站路线成功尚未通过，只有地点间Provider步行路线通过。
- 新UI完整锁屏、进程死亡、断网、令牌失效和未知确认的真机矩阵尚未完成。
- 附近筛选/地图列表/比较已有真实接入与状态保留，但本轮完整手机闭环尚未验收。
- 新UI的Recovery Reject/过期/并发全部反例仍需补测；不能用后端测试取代手机结果。
- 原生页面的信息层次和旅程流程已向新版Web对齐；AI轻量情境唤起/展开关系、长草稿触控与部分图标细节仍需继续打磨，不能宣称所有页面体验已完全统一。
- APK仅USB隔离预览连接；不具备已部署的独立公网服务。未发布公网或扩大网络暴露。

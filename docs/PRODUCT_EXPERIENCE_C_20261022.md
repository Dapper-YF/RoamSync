## 3. 用户真正需要的核心价值

用户反复回来，不应是因为这里有另一套长攻略，而应是因为：**我已经选过什么、还没决定什么、今天怎么走、临时改了什么，都能在这里找回并继续执行。**

理想连续流程：随便聊聊/搜地点 → 比较真实选择 → 记下一个打算（不要求日期） → 请 AI 协调 → 看懂差异后采用 → 在路上查询下一站、休息或调整。内部仍可使用 Trip、PlanningRun、Revision，但用户看到的是地点、某一天和自己的决定。

收藏是兴趣，打算是明确选择，日程是采用后的安排，执行进度是用户记录的实际发生。不能因为收藏、问天气或浏览地图就把后面几层自动写入。

目前产品已有保存、真实地点、地图、正式写保护和执行基础，能够支撑这个价值的部分链路。自然修改和新建规划的可靠性仍不够，尚不能证明长期使用理由已被完整兑现。

## 4. “我的安排”方案比较

| 方案 | 用户操作流程 | 实际收益 | 代价与判断 |
|---|---|---|---|
| A：常驻日程＋聊天双栏 | 看第二天 → 在右栏说“人民公园改下午” → 左栏切候选 → 核对采用 | 长时间密集协商时来回切换少，桌面能同时对照 | 聊天长期占宽度；手机必须堆叠/切页；看日程也被对话吸走。不是默认方案 |
| **B：日程优先＋按需上下文助手** | 选第二天/点某站“和AI商量” → 抽屉里自然说要求 → 回日程看完整差异和保留项 → 采用 → 返回正式日程 | 默认容易看安排；对象不用重复说明；手机底部面板沿用单一会话输入；确认和结果在同一地方 | 打开助手多一次点击；补上日程前部入口和“回到日程查看完整改动”可减轻。**本轮选择** |
| C：地图优先＋底部日程/助手 | 点地图地点 → 看附近/相对位置 → 拉开日程 → 请求顺路调整 | 旅中找附近、比较空间关系更自然 | 地图不擅长表达钟点、预约和未排程；弱网、无坐标事项难处理；作为探索/地图视图继续存在，不作为安排默认页 |

对“第二天别排太满”：B保留第二天上下文，AI先提案，日程说明移除/改时/保留内容；对“武侯祠先留着不排钟点”：它留在未排程分区，不要求填时间；对雨天咨询：应给建议而不默认改日程；后两种自然语言的普遍正确性仍需 B 的语义与事实评测。

本轮延续既有照片手册方向，没有引入另一套日程存储、第二个聊天器或手填排程表单。

## 5. 已实施的真实交互

- 探索成功留在探索页；URL可刷新恢复；旧根路径搜索书签重定向；收藏、空状态与场景恢复回到正确探索页。
- 保留实景封面和活动照片，缩短首屏装饰；概览不重复显示大照片/活动操作，保留“查看这一天”。
- 日期附近显示当天已排事项摘要和上下文调整入口；AI平时不占日程栏，桌面按需侧栏、手机按需底部面板。
- 采用前在日程上方复核所有相关日期的新增、移除、时间、时长、地点、预计费用和固定时间变化；保留内容可展开，范围外日期明确列出。无范围元数据时按全旅程复核，不声称其他日期自然不变。
- 新候选自动选择实际有变化的日期；助手提供返回完整复核链接。“返回原安排”只关闭预览，“继续商量”不触发 Reject。
- 版本过期、基准版本无法核对、包含旅行外日期时禁用采用。网络失败保留候选；刷新重新读服务器；最终调用原 Accept。
- 修正重复到访同一地点的预览匹配：明确替换ID优先，不用同名地点把两次到访合成一项。地点替换用新坐标，不把旧地点画到地图上。
- 时间轴呈现开始/结束和固定时间；当天未排程事项、整趟未定日期、明确自由时间区分。没有把一般空档自动标成用户要求的留白。
- 地图采用适合当前容器的边距，避免旧工作台430px侧栏预留挤压手机视野；真实高德1440/390/320各两处标记均在视野内且可点击关联日程。交通跟随对应活动，显示“前往某站”；没有路线时如实显示未查询；预览不展示旧安排的交通数字。
- 手机点击目标至少44px；澄清输入在页面级会话状态中恢复。手动时间编辑与执行能力沿用现有入口与保护。

## 9. 未解决问题与路线

1. **先修兑现能力**：B解决留白误识别和规划检索可用性，A组合验收失败降级/恢复；初始空旅行和已存在旅行分别验收。
2. **再改善回访入口**：首页展示一项可继续的安排/打算，独立打算更容易找；避免把所有内部状态做成首页卡片。
3. **再试地点比较MVP**：最多三处、同一地图、已核实差异和个人取舍，验证用户是否更容易决定；先不做目的地内容平台。
4. 后续再做两小时附近出游与旅中换站；最后考虑跨会话个性化、持续GPS导航和协作。

视觉验收无法证明单手舒适度、留存率与推荐质量。地图依赖网络和既有高德配置；天气/营业时间/真实预约仍不能由照片、锁定时间或用户原话冒充已核验事实。产品层仍存在较大的DiscoveryApp/TravelAssistant及层叠样式债务，本轮只增加独立复核组件和纯展示适配，没有做与价值无关的整体重写。

**普通用户长期使用的理由应是“这里记得我已做的决定，并能把新的需求安全地接续到真实行程”。现在已具备部分可靠基础，本轮让它更容易看懂和操作；但模型语义和检索故障仍会打断兑现，所以目前只能回答：部分支撑，尚未完整支撑。**

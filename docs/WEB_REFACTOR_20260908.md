# RoamSync 前端重构：首轮交付

日期：2026-09-08。以实际源码和本次验证为准；旧 README、审计报告中的旅中模式描述属于历史实现。

后续的模型连接、交通校验和首次日期覆盖修复见 [真实 AI 流程修复](AI_FLOW_REFACTOR_20260908.md)。下方真实 AI 失败结果为首轮验收记录。

## 已落地的产品边界

- 一个旅程工作区、一位旅程总管。`/assistant` 兼容跳转到 `/trips/new`；`/trips/:id` 为统一入口，旧 `/planner` 链接仍可打开。
- 新建首屏只填写目的地、日期、预算和补充要求。住宿、名称及详细偏好折叠；创建后打开当前旅程的助手。偏好保存失败重试复用已建旅程，避免重复创建。
- 默认显示行程，地图按需加载。日期覆盖今天时默认选中今天，否则选中第一天。首页与详情的阶段由浏览器本地日期推导，归档状态优先。这是展示规则，不自动写入执行记录。
- Web 移除开始、暂停、恢复、结束旅行和独立动态重规划弹窗。单个活动支持完成、跳过、恢复为待游玩，通过已有活动接口持久化。
- AI 请求区不再预填“第 2 天下午”。首次规划发 `initial_plan`，后续调整发 `replan`，同时传当前选中的日期和活动。
- 助手恢复未完成的历史任务，展示澄清、待确认、已应用和失败状态。澄清直接返回候选时立即加载候选。确认后保留面板反馈。
- 首次规划在生产 Worker 的编排链路中准备带来源的高德候选地点；候选入库不等于加入正式行程。地点采集失败会失败退出，模型不得把空首次方案当作成功，前端也禁止接受旧的空首次方案。
- 页面移除数据库、模型编排技术文案及尚未实现的复盘承诺。预算仍是规划预估，未新增真实预订、支付或自动消费采集。

## 验证边界

- 前端测试覆盖旧链接跳转、创建失败重试、直接完成活动、AI 初始参数、澄清恢复、刷新后候选恢复及历史读取失败。
- 后端测试覆盖首次地点采集去重、来源保存、无正式活动写入、无搜索结果失败和空模型结果拒绝。
- 浏览器回归使用独立复制的演示旅程，结束后归档副本；不再调用 `/demo/reset`，不覆盖用户旅行。
- 视口覆盖 1440、1024 和 390 像素。真实 AI 验收使用单独的“重构验收 20260908”旅程，保留供复查。

### 本次实际验收结果

- 前端单元测试：34 项通过；lint、TypeScript 检查和生产构建通过。
- 后端测试：136 项通过，使用独立测试数据库；存在 2 条既有弃用警告。
- Playwright 浏览器回归：9 项通过，包含移动端、地图切换、活动完成后刷新、跨日移动及截图基线。
- 本地 Docker：API、Web、PostgreSQL 健康检查通过，Agent Worker 运行中。访问 `http://127.0.0.1:3000/trips` 可查看本轮版本。
- 真实 AI 验收尚未闭环。独立旅程 ID 为 `1f7914dc-849f-4325-94ad-e5e2518931f9`：首次地点采集已执行，生成结果曾因 `route_travel_time_conflict` 被拒绝；后续两次生成因模型服务 `APIConnectionError` 失败，正式行程未被改写。
- 从 Worker 单独读取已配置模型服务的模型列表，也复现了 `APIConnectionError → ConnectError`。此前 DNS 和 TCP 443 检查通过，但这不能证明 HTTPS/API 请求成功。未修改模型密钥、放宽路线校验或用模拟结果冒充真实成功。
- 因此，本轮已通过页面及交互回归，真实“生成候选 → 确认应用 → 刷新保持”的生产模型链路仍需在连接恢复后验收；不能据此宣布 AI 功能整体可用。

## 明确未完成的后续工作

1. 通用多轮对话与长期对话记录：当前仍是持久化规划任务和澄清恢复，不是完整聊天会话。
2. 完整变更对照及已应用方案撤销：现有接受/拒绝可用，尚未新增通用撤销接口。
3. 旅行后复盘、费用总结、照片和附件：本轮未新增页面或虚假占位功能。
4. Android 仍有原执行 API。Web 活动状态与旧执行事件的全双端一致性需要下一轮领域迁移，暂不删表和历史记录。
5. 目的地跨时区、主动天气监控、GPS 自动判断、离线和多人协作均未在本轮实现。
6. 继续拆分 App.tsx 中的列表、创建和旅程数据加载，避免后续继续向入口文件叠加功能。

本地 Docker 的 API、Worker 和 Web 重新构建，数据库卷保留。现有未提交修改继续保留，不自动提交或推送。

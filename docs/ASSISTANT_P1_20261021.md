## 主动配图

一次语义决策判断当前问题是否值得配图；回答模型在原回答 JSON 中提供最多三个具体主题。
服务端只查询最终正文实际出现的主题，最多两个并行查询；地址、天气、日期、游玩天数、
确认与普通条件回忆不因为顺带提及景点而强制查图。查图是独立图片补充，不把文字常识
变成“联网核实”，不把图片来源加入事实证据引用。

图片仅来自实际供应商响应，复用既有 HTTPS、安全地址、明确主体/菜品和相关性校验；
不接收模型编造的 URL，不代理下载远程图片，不猜测版权许可。单次图片查询不自动重试，
可选图片工作最多 18 秒且受咨询剩余总预算约束。实际原查询一次约 14.3 秒，初版 7 秒
过短导致超时，已调整；失败保留正常正文和安全关联诊断，回答不会因此变成 failed。

用户要求不显示“参考图”标签：已移除徽标及替代文字中的该字样；主题/使用依据仍留在
服务端元数据中，来源和已有许可信息保留在 ⓘ。图片按主题匹配正文段落，优先放在
对应介绍旁，每段最多一张；桌面端图片最大宽190px/高132px，文字及后续段落自然环绕，手机端缩小后随正文换行。
没有单独的大图画廊。图片加载成功前不占位，加载失败移除，不留下空卡片。

用户说“以后不用配图”会在同一对话保存；明确恢复配图或开启新对话后可重新配图。
搜索图片是说明性材料，来源可查看，不代表现场状态、已核实分店或实时事实。

## 有效会话条件

现有会话 JSON 的 ContextEnvelope 可选增加 `conversation_memory`，记录城市、锚定的
出发日期、天数、同行人数、预算、偏好、要求和配图选择。每项保留用户原句和来源消息 ID。
语义决策在同一个模型调用中提取条件增量；服务端检查当前用户原句，忽略客户端伪造的
记忆、引用内容、别人的条件和假设方案。明确日期/天数补充也有小范围确定性解析，供
既有规划澄清流程复用；条件更新不能获得正式行程写入权限。

后续回答、事实/地点决策及规划路由读取当前有效条件。新值覆盖旧值，明确撤销或替换
从有效偏好中移除旧条目；旧原句仍留在原聊天消息中。相对日期按陈述当天的上海日期
锚定，刷新或隔天继续聊不会把原先的“明天”重新计算一次。常见月日、ISO 日期与周几
由服务端解析，无法确认的日期不会擅自补成一个具体日期。

更换城市保留日期、天数、个人饮食/兴趣/节奏要求，清除旧地点焦点和绑定旧目的地的要求。
新话题的 epoch 让旧建议和旧条件不再进入当前提示。明确新话题或新的 UI topic 不能
借用旧 Trip；原来的 Validator、Accept、幂等与版本检查继续保留。

“新对话”按钮调用兼容的 `POST /assistant/sessions` 可选 `new_session=true`，创建独立
空会话；不能同时指定旧 session/trip。旧聊天及待确认内容留在旧记录，不删除，也不
出现在新会话。刷新后恢复新会话。旧客户端缺少新字段仍照常工作。

历史消息没有有效条件快照时，可保守恢复同范围内明确的用户城市、绝对日期和偏好；
缺少原始陈述时间的旧相对日期不能重新锚定，不能声称历史信息已被完整恢复。

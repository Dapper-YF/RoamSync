## 本轮修复

### 模型连接

本机启用了 `127.0.0.1:7897` 系统代理。Worker 直连模型域名时，DNS 曾返回 `198.18.0.168`，TLS 握手报 `UNEXPECTED_EOF_WHILE_READING`。使用现有系统代理后，模型列表请求成功。

新增可选 `PLANNER_PROXY_URL`，由规划模型和意图理解模型共用。默认留空保持原部署行为；本地 `.env` 配置为 `http://host.docker.internal:7897`。此设置依赖本机代理服务可用，不修改系统网络或关闭证书验证，不改变 API 密钥。其他机器应使用自己的代理地址或留空。

构建时曾遇到相同的依赖下载 TLS 问题，使用 Docker 的临时 `HTTP_PROXY` / `HTTPS_PROXY` 构建参数完成下载。Dockerfile 已把依赖安装放到源码复制之前，并缓存 uv 下载，后续源码修改不再重复下载依赖。

### 交通时间冲突

系统先查询真实路线，再检查活动间的时间。如果冲突仅涉及重叠或交通时间不足，会按现有路线顺序尝试顺延后续活动；不改变地点、游览时长、费用或交通方式。

遇到已锁定、已完成活动或每日结束时间限制时，不采用这次自动顺延。顺延后仍需通过完整校验，包括预算、作用范围和来源。无法自动解决时，保留原来的有次数上限的模型修正；最终仍不满足则失败，正式行程不变。

高德只读查询在网络瞬断或服务端错误时最多重试一次；配额及其他客户端拒绝不盲目重试，未打开估算路线兜底。

### 完整日期覆盖

真实验收发现：默认选中的第一天被当成首次规划范围，导致“三天完整行程”只生成第一天。现已修正：

- 空旅程首次请求不再携带默认日期和活动选中项。
- 明确的全程请求优先于页面默认选中项；明确指定第二天的请求仍保留局部范围。
- 包含旅行起止日期的完整规划请求不会被缩成起始日期。
- 首次完整方案需要覆盖全部旅行日期。缺少日期时先要求模型补齐；仍缺失则返回具体日期，不生成可接受的候选。
- 候选记录保存所需覆盖日期，接受时再次检查。旧历史候选不回写补造这个字段。

### 失败后的下一步

新增迁移 `20260908_0017`，为规划任务保存结构化失败详情。界面展示实际的时间、日期或预算冲突，提供减少冲突日期地点、优先免费地点、补齐日期等可编辑的补充要求。连接错误支持重试原需求。

关闭再打开助手时，优先恢复未完成任务；没有未完成任务则恢复最近一次结果。成功、拒绝和失败记录继续保留。

### 局部调整与节奏

按天重规划补齐范围外活动的后端保留逻辑。另修复“节奏更轻松”等表达没有被识别的问题；已有安排要求放轻松时，增加当天地点数量的候选会被拒绝并要求修正。这是对地点数量的基本约束，不代表已全面量化疲劳或舒适度。

# Android 0.2.0 移动端重构

2026-09-09。保留 Kotlin / Jetpack Compose 原生工程与包名 `com.roamsync.app`，替换旧版“创建旅行—预算”主流程。与 Web 共用服务端数据和旅程总管，不使用 Web 页面作为应用外壳。

## 页面与交互

- 行程首页：品牌图标、AI 创建入口、手动创建、按日期状态筛选的旅行卡片。
- 行程详情：按天切换、时间与费用、备注、交通距离和时长、冲突提示。活动可编辑开始时间、停留时长、费用、备注和时间锁。
- 地图：高德底图、编号地点、已有路线几何，步行/公交/驾车重算，外部地图导航。仅地图区域使用 WebView；显式设置地图高度，防止初始化高度为零；提供加载失败和渲染进程异常的恢复入口。
- 预算：区分计划支出与实际消费；分类记账，保留重试幂等键，避免预算刷新失败后重复入账。
- 旅程总管：全屏原生对话，首页与行程内共用助手；区分答复、澄清、生成中、待确认、已保存和失败状态。支持创建、参考旧旅行、改期的工具确认，以及行程候选方案解释与确认。
- 输入支持软键盘发送、硬键盘 Enter；Shift+Enter 换行，避免输入法组合状态下误发送。未发送草稿保留在 SavedStateHandle，关闭助手不需要等待后台任务完成。

## 数据一致性

- 助手直接使用 `/api/v1/assistant/sessions`、messages 和 decision 接口，确认前不自行写行程。
- 候选方案使用 planning-runs / revision / decision 接口。客户端必须读到 run 与 revision 均为 accepted，随后重新读取 trip、days、budget。
- 保存成功后读取失败会明确提示“方案已保存，但正式行程读取失败”，不会假报未保存。
- 活动修改携带 version；冲突时提示刷新。恢复助手优先读取最新服务端任务，避免旧会话指针遮住 Web 创建的新任务。
- 旅行状态根据旅行时区和日期显示，不提供开始/暂停旅行按钮。

## 联调修复

- 补充“只回答、只分析、游玩的理由”等咨询识别，避免只读问题被误路由到修改行程。
- 补齐目的地研究相关错误码的响应枚举，避免已持久化的失败任务导致 GET task/history 返回 HTTP 500。

- Android：`assembleDebug`、`testDebugUnitTest`、`lintDebug` 通过。13 项测试：金额转换、保存后读回、拒绝方案、消息重试幂等、澄清续接、日期范围、历史任务恢复、手动创建、助手创建等。Lint 为 0 errors，仍有依赖升级/旧资源等 warnings。
- 后端：独立测试数据库中 113 项意图/助手测试通过；5 项研究错误码响应契约测试通过。初次使用旧测试库时发现历史会话污染，改用独立 `roamsync-mobile-qa` 项目后通过。
- USB 真机：更新安装、启动、读取旅行和预算；已查看原生首页和对话界面。
- 独立 Android 模拟器：行程页、真实高德地图、预算、历史会话与澄清界面；通过原生确认按钮把独立测试旅行从 9 月 5–6 日改至 10 月 3–4 日，状态变为 upcoming，5 个活动保留；通过原生界面记账 12.50 元，API 读回 1250 分。

- 一条包含新测试删除请求与安装的组合命令被自动审批拒绝（仅返回 blocked by policy），未继续执行该命令；安装通过独立命令完成。
